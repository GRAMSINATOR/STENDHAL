# Workflow — Rewrite / transfer style

Use when the article already exists and the user wants another publication character, register or house voice.

## Rule zero

Style transfer may not alter facts, quotations, evidential certainty or substantive meaning unless the user also asks for editorial restructuring.

## 1. Freeze the source

Build a small ledger of:
- claims;
- quotations;
- numbers;
- names;
- dates;
- caveats;
- unresolved uncertainty.

## 2. Diagnose the existing article

Identify:
- format;
- proposition;
- current beat map;
- current style vector;
- passages whose wording is fact-sensitive.

## 3. Load the target

Read `brain/07-style-engine.md` and the target profile.

List the meaningful differences:
- information order;
- compression;
- scene;
- judgement;
- authorial presence;
- rhythm;
- marked language;
- ending.

## 4. Decide structural permission

If the user asked only for stylistic rewriting, preserve the story spine unless modest reordering is necessary for target readability.

If the target style really requires a different structure, say so internally and use the closest compatible version rather than inventing missing reporting.

## 5. Rewrite in layers

Order of change:
1. paragraph function;
2. sequencing;
3. compression/expansion;
4. transitions;
5. sentence rhythm;
6. diction;
7. conspicuous voice devices.

Do not begin with synonym replacement.

## 6. Verify fidelity

Compare rewritten copy against the frozen ledger.

No new:
- facts;
- implications;
- certainty;
- motives;
- chronology;
- quotations.

## 7. Run adversarial edit

Use evidence, line/rhythm and slop/comprehension editors.

A successful style transfer should remain recognizably the same reported reality while feeling built by a different editorial machine.
